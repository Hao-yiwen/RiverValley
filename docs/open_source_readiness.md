# 开源准备审查

日期：2026-11-16。结论：项目以“从零训练 1B 的研究与工程实验”定位公开源码，尚不宜以“可靠的通用中英文助手”发布。所有者已授权从干净快照建立独立的 [公开源码仓库](https://github.com/Hao-yiwen/RiverValley)，不继承原开发仓库的 Git 对象、旧 MR 或历史分支。所有者随后要求公开实验权重下载，许可和署名核查仍未完成；原开发仓库继续私有，旧缓存、凭据有效性及权重许可仍按下文继续核实。

## 审查范围

初次准备对本地所有 refs 可达的 2,068 个 UTF-8 文本 blob 执行规则扫描，24 项二进制或过大对象跳过，在云端文档的 6 个历史 blob 中命中 12 处登录密码规则。用户随后明确要求合入 main、清理敏感信息并上传检查点。本轮删除当前私人配置，使用 git-filter-repo 敏感信息清理模式重写受影响历史；全部 5 个远端可写分支完成核验，其中 4 个分支需要更新，并使用精确版本租约与原子推送完成。main 当前代码树在历史重写前后完全一致。

清理副本全部可达引用共检查 590 个 Git 对象，包括 54 个 commit 和 347 个 blob；已确认的历史密码命中为零，旧私人路径不再可达，Gitleaks 8.30.1 扫描发现为零。GitHub 旧 MR 的只读引用不在可强推范围内。上述检查不能证明所有凭据形态、平台缓存或外部克隆均已抹除。GitHub 仓库仍为私有，本轮没有重训或申请云端实例。

## 未解决发现

原位置：已删除的私人云端文档及其历史版本。本轮已从当前文件和全部远端可写分支历史中清除，并删除各历史中的本机助手设置。通用部署说明改为 `docs/cloud_training.md`，CI 增加全部 Git 跟踪文件检查。

剩余事项：GitHub 旧 MR #1 / #3 的只读引用及缓存需要 GitHub 支持协助清除。已于 2026-11-16 通过官方支持门户提交申请，并看到提交成功页面；工单如实说明旧凭据是否失效尚不确定，没有附明文凭据。提交成功不等于缓存已删除，当前等待支持团队答复，门户尚未返回可记录的工单编号。原开发目录的未提交工作、旧本地历史与受限备份被保留，不能直接用旧克隆把旧分支重新推回远端。账户所有者已答复“无法确定是否失效，请先保持私有”，因此该阻塞项保持未解决。

### W1 · WARNING：最新权重尚不能确认适用 Apache-2.0

位置：`configs/*sources.lock.json`、正式 V2 数据清单、最新翻译修复材料及上游数据卡。OpenCSG 数据正文带有额外社区协议及商用授权表述；实际使用的 COIG-CQIA / Magpie 许可不完整，Tatoeba 署名还需整理。

处理方案：源码使用已选定的 Apache-2.0；所有者要求先公开实验权重下载，模型卡保留许可缺口，暂不填写权重许可证，也不宣称可自由商用。固定版本证据、README 摘要和询问回执见 `release/license_review.json`。所有者授权后，已向 OpenCSG 指定联系人发信，并在 COIG 与 Magpie 现有许可讨论中发布询问，等待明确答复。Tatoeba 已新增 23,052 个句子 ID 的当前署名索引，孤儿句、缺失句与历史作者完整性仍有待确认。具体来源、实际纳入与排除关系见 [数据来源](data_sources.md)。不把下载过的 OPUS-100、Alpaca 中文或草案中的 OpenCSG smoltalk 错计为最新正式 SFT 的实际来源。

### W2 · WARNING：公开介绍必须收窄能力承诺

最新候选新留出翻译仅 12/48 完整正确；旧开发常识 3/20 分、算术 4/40 分。开发集和留出集均为内部评估且句组相关，由 Codex 复核，没有独立用户验收。训练完成、验证 loss 下降与局部格式任务提升不能代表通用聊天达标。

处理方案：README 和模型卡已统一使用实验性定位，保留分母、句组数、候选选择顺序、无起点留出对照及源句质量限制。原始回答没有被本次准备流程重写。

已验证的本机环境为 Python 3.12.8、PyTorch 2.9.0、Transformers 4.57.3。没有重新验证所有 CUDA、多卡、MoE、DPO 或 GRPO 路径，也没有完成全部依赖的漏洞扫描。原开发仓库的全部现有 CI 检查已通过；独立公开仓库会重新运行 [GitHub Actions](https://github.com/Hao-yiwen/RiverValley/actions/workflows/tests.yml)，检查结果不等于所有平台与扩展训练路径均已验证。
